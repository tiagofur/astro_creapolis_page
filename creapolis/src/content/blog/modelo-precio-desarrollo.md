# Modelos de precio para desarrollo de software: cómo cobramos

Una de las preguntas más difíciles: ¿cuánto cuesta? Y la respuesta honesta es: depende.

## Modelos disponibles

### 1. Por hora (Time & Materials)

**Cómo funciona:** Cobras por cada hora trabajada.

**Pros:**
- Flexible — el cliente puede agregar o quitar scope
- Solo paga por lo que usa

**Contras:**
- El cliente no tiene visibilidad del costo total
- Sin incentive to be eficiente
- Puede escalar way más de lo esperado

**Cuándo usarlo:**
- Proyectos con scope muy incierto
- Work de mantenimiento pequeño
- Cuando el cliente quiere mucho control

---

### 2. Precio fijo (Fixed Price)

**Cómo funciona:** Acordás un precio por todo el proyecto.

**Pros:**
- El cliente sabe exactamente cuánto va a pagar
- Incentiva eficiencia (el dev gana si termina antes)

**Contras:**
- Riesgos both ways (cliente gets more if scope grows, dev pierde si subestimó)
- Menos flexibility para changes
- Requiere scope muy bien definido

**Cuándo usarlo:**
- Projects con scope claro y bien definido
- Landing pages, MVPs simples
- Cuando el cliente tiene presupuesto fixed

---

### 3. Retainer mensual

**Cómo funciona:** El cliente paga una mensualidad fija por un set de horas o features.

**Pros:**
- Predictibilidad para ambos
- Relationship a largo plazo
- Flexibility para prioridades changing

**Contras:**
- Requiere confianza mutua
- El cliente tiene que tener trabajo consistente

**Cuándo usarlo:**
- Mantenimiento y evolución continua
- Startups que necesitan ongoing development
- Cuando hay una relación establecida

---

### 4. Producto propio (Equity)

**Cómo funciona:** Desarrollamos a cambio de equity del producto.

**Pros:**
- Shared risk, shared reward
- Alineación de incentivos

**Contras:**
- Solo funciona para proyectos con potencial real
- Requiere evaluar cuidadosamente el opportunity
- Más complejo legal y operacional

**Cuándo usarlo:**
- Startups con buena idea y buen equipo
- MVPs con potencial de scale
- Cuando el founder tiene lo que falta (product, market, domain expertise)

---

## Nuestra recomendación

| Tipo de proyecto | Modelo recomendado |
|------------------|-------------------|
| MVP / Producto nuevo | Fixed price con milestone payments |
| Mantenimiento | Retainer mensual |
| Startup early-stage | Equity o fixed price |
| Sitio web / landing | Fixed price |
| Feature específica | Fixed price o time & materials |
| Consulting estratégico | Retainer |

## Nuestra estructura típica

Para proyectos fixed price:

- **30%** al inicio (commit)
- **30%** al diseño aprobado
- **40%** al launch

Para retainers:

- Facturamos monthly, semana a semana
- Includes un set de horas (ej: 20h/mes)
- Extra hours se facturan a tasa preferencial

---

## Por qué no cobramos solo por hora

Porque no beneficia al cliente. Con hourly:
- El cliente no tiene incentive a dar feedback rápido
- Nosotros no tenemos incentive a ser eficientes
- Both parties lose

Preferimos fixed price cuando el scope está claro, porque:
- Ambos sabemos dónde estamos
- El cliente puede presupuestar correctamente
- We both win cuando entregamos eficiente
